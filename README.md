# YgoGuess · 游戏王多人猜卡

React / TypeScript / Vite 前端，Node.js / ws 服务端。本地使用文件缓存 + SQLite，生产支持 Redis + MySQL。首版单 Node 实例，同源提供网页、HTTP 和 WebSocket。

## 游戏版本号

版本制度从 **1.0.0** 开始；当前版本以 `package.json` 的 `version` 为准。构建后的网页会在右上角以小字显示对应版本，`package-lock.json` 与其同步。`RoomState.version` 只是房间状态修订次数，不是游戏版本号。

每次更新涉及 WebSocket/HTTP 消息结构或通信行为，以及回合、猜测、计分、房间管理等核心功能时，都要在发布前推进游戏版本号。采用语义化版本：不兼容的协议或存档变更升主版本，兼容的新功能升次版本，兼容的核心修复升修订版本。只改前端样式、布局或页面文案时不需要推进版本号。使用 `npm version patch --no-git-tag-version` 同时更新 `package.json` 和锁文件；需要升次版本或主版本时，把 `patch` 换成 `minor` 或 `major`。随后构建、测试并部署；不要单独修改页面上的版本文字。

## 本地启动

需要 Node.js 24。项目提供 `.nvmrc`；先安装并切换到 24，再用 `npm ci` 按锁文件安装依赖，避免安装时改动 `package-lock.json`。Node 25 会被 `.npmrc` 中的 `engine-strict` 拒绝：

```powershell
nvm install 24
nvm use 24
npm ci
Copy-Item .env.example .env
npm run dev
```

本机交付已有 .env，无需覆盖。打开 http://127.0.0.1:3131 。局域网其他设备访问 `http://本机局域网IP:3131`；需要处于同一网络并允许该端口入站。浏览器即可游玩，无需客户端安装。

正式运行：

```powershell
npm run build
npm start
```

HOST / PORT 可在 .env 修改，默认 0.0.0.0:3131。开发模式支持热更新，生产模式使用 dist/client 静态文件。Ctrl+C 停止服务。

### 本地道具卡调试控制台

运行 `npm run dev` 后，以房主身份创建房间，展开房间页面中的“道具卡调试控制台”。只有开发模式的房主能看到并调用它；`npm start` 的正式服务会拒绝调试命令。

- 一个人测试：在空房间点击“一键开始单人测试局”，系统加入一个“测试玩家”，分配本地保存的「青眼白龙」与「黑魔术师」完整卡图并进入猜卡阶段，不需要第二个浏览器或外部卡牌接口。
- 选择玩家和卡牌后，点击“发卡并切到他的回合”；如果选的是自己，道具卡会立即出现在自己的手牌中，可按正式流程选择目标并使用。也可以只发卡、单独切换回合或清空手牌。
- 用“设置次数并恢复参赛”“模拟猜错出局”准备抢夺卡、苏生卡等目标；“清除卡牌视觉效果”可检查限时外观的恢复；终焉卡发动后可把倒计时设为剩余 1 回合，再正常结束下一玩家回合查看结算。

测试玩家没有真人操作，但在开发测试局中可作为在线目标。调试操作只改当前开发房间，不改变正式卡池权重或道具卡使用规则。

## 游戏规则

- 输入昵称创建或加入六位房间码。2–10人；所有非房主玩家准备后，房主开始。
- 默认3局、每人每局3次猜测，建房分别可选1–20局、1–10次。
- 默认开启道具卡；每小局每位玩家第 3、6、9……次轮到自己时各抽 1 张，仅自己回合使用，用后消耗。卡池目前包含禁止、增殖、假面、机会、雷击、火球、外神、神愤、指名、扫描、月书、苏生、虚无、逆转、谜题、提示、丝袜、小丑、友情、团结、终焉、抢夺、鲜花、看透、魔术、旋风、风暴、陨石、地碎、日书、天变、音乐卡；无效果测试卡保留但不参与抽取。详见 [道具卡框架](docs/item-cards.md)。
- 开局前房主可在房间内修改模式、局数和每局猜测机会；保存后其他玩家须重新准备。开赛后规则锁定。
- 开局前房主可反复点击“打乱顺序”；服务端随机重排座位，并在聊天中公布新顺序。打乱不会取消已准备状态，好友出题的下家及猜题回合均按新座位顺序执行。两种模式均可使用，开赛后不可再打乱。
- 好友出题：给座位顺序的下家选卡，末位给首位；全部提交后开始。提交后锁定。
- 随机分配：从精选题库抽取，同局不重复。当前正式题库包含 1,855 张卡牌。
- 本局参赛者在猜中前只能看见其他参赛者的题目；猜中后自己的卡牌立即显示。未猜中的自己的答案不下发给自己的浏览器。点击卡图可放大并阅读文字。
- 卡牌名称优先显示百鸽提供的 YGOPro 译名（搜索/批量结果的 `cn_name`，单卡详情的 `text.name`）；缺少时才回退到其他译名。例如密码 5318639 显示为“旋风”。
- 所有阶段均可聊天。轮到自己时，从搜索下拉选定卡牌再猜；无论对错，自动结束回合。主动或强制跳过不扣猜测机会；也可二次确认放弃本局，剩余机会清零并退出本局轮转，聊天中会通知大家。
- 回合不限时。猜对或机会用完后退出本局轮转，仍可聊天；所有人完成后结算。房主进入下一局，不需重新准备，每局轮换首位行动者。
- 猜对得分为 max(1, round(1000 / 本局个人经历的回合数))，失败0分；主动及强制跳过也计入回合数。多局累计，同分并列。
- 中途加入者本局观战、下局参赛；猜题阶段可以看到本局所有参赛者的卡牌并聊天。出题阶段不显示尚未公开的牌；结算后可查看答案。下局成为参赛者后，自己的牌再次隐藏。
- 刷新、短暂掉线、服务器重启后可恢复身份和局面，需保留浏览器Cookie。掉线不扣次数、不跳回合。检测到房主断开30秒后，转交最靠前的在线玩家；全员离线时保留状态，直至闲置清理。
- 服务启动时及之后每小时清理一次已关闭房间和连续 3 小时没有成功操作的房间；在线成员会退出房间并返回大厅。聊天、加入、游戏操作和绘画计入活跃，连接心跳和系统自动操作不计入；因此闲置房间通常在最后操作后 3～4 小时内被清理。清理删除内存和数据库中的房间状态，保留历史比赛结果、管理员审计和用户会话。旧房间缺少活跃时间时，从创建时间、已处理操作和用户聊天推算。
- 房主可在其他玩家卡片上点击“移除玩家”，确认后将其踢出房间。主动退出/被移除后保留已得积分，未完成本局记0分。有效参赛者不足两人时提前结算。出题阶段参赛者离开会重排下家、清空出题；等待下局者离开不影响当前出题。
- 主动退出或被移除后，只要房间仍开放且未满 10 人，就可以用原游客身份重新加入；累计积分保留，本局不恢复猜题资格，从下一局参赛。房主在结算后“再来一场”仍会重置积分。
- 打开另一个房间的邀请链接时，页面优先展示邀请目标，并提供“加入新房间 / 留在原房间”。选择加入后，服务端先校验目标房间，再将退出旧房间和加入新房间作为一次数据库事务保存；无效或已满的目标不会使玩家离开旧房间。直接刷新且没有新邀请时仍恢复原房间。

## 精选题库

`config/card-pool.json` 已填入 1,855 个精选卡牌密码。随机模式要求不同有效 cid 数量至少与参赛人数相同。每次开局重新加载，无需重启；服务器按每批最多 100 张查询百鸽并缓存结果。

```powershell
npm run cards:validate
```

好友出题直接使用[百鸽API](https://ygocdb.com/api)，不受精选题库为空影响。搜索支持模糊输入、下拉选择、方向键/Enter、加载更多。服务器缓存卡牌响应，上游故障时可使用7天内的已有缓存，无缓存则提示重试。牌桌用half卡图，搜索用thumb，放大时加载原图；卡图故障仍可查看卡名与文字详情。

## 超级管理员

在 .env 配置 ADMIN_ENTRY_KEY，空值会关闭特殊入口。本机交付已生成随机密钥，仅保存在被Git忽略的 .env 中。

```powershell
npm run admin:url
```

运行后在自己的终端查看入口，或访问：

```text
http://127.0.0.1:3131/admin/entry?key=你的密钥
```

服务端校验后设置HttpOnly / SameSite Cookie并跳转到不含密钥的 /admin。管理员可以查看房间、强制跳过、移除成员、转移房主、解散房间；管理界面不显示任何答案。管理操作服务端鉴权并记录审计。

普通玩家仅使用昵称游客身份；清除Cookie后不能仅凭昵称取回原身份。管理员会话默认有效30天；轮换密钥影响新的入口访问。立即撤销已有会话时，停服后删除数据库中对应管理员会话记录再重启。

## MySQL / Redis 与 Docker

本机没有这两个服务也能使用SQLite版本。切换环境变量：

```dotenv
STORAGE=mysql
CACHE=redis
MYSQL_URL=mysql://ygoguess:password@127.0.0.1:3306/ygoguess
REDIS_URL=redis://:your-redis-password@127.0.0.1:6379
```

Redis 使用默认用户的密码格式为 `redis://:密码@主机:端口`；使用 ACL 用户时改为 `redis://用户名:密码@主机:端口`。密码中的 `@`、`#`、`:` 等特殊字符必须按 URL 编码，例如 `pa@ss#1` 写成 `pa%40ss%231`。如服务端要求 TLS，使用 `rediss://`。Redis 服务端也必须配置相同的密码，单改应用的 URL 不会给 Redis 设置密码。

事先创建数据库，使用utf8mb4并授予用户建表权限；应用首次启动自动建表。房间、结算和管理员审计在同一事务中提交，成功后广播；Redis只缓存可重建卡牌数据。

Docker Compose 包含应用、MySQL 8.4、Redis 7。在 `.env` 增加 `MYSQL_PASSWORD`、`MYSQL_ROOT_PASSWORD` 和 `REDIS_PASSWORD`（建议使用随机十六进制字符串，使 Redis 密码可以直接写入连接 URL）。Compose 会给 Redis 启用密码，并将同一个密码传给应用：

```powershell
docker compose up --build -d
```

应用暴露3131端口；MySQL和Redis仅内部访问。MySQL数据保存在mysql-data卷。HTTPS反向代理后设置 COOKIE_SECURE=1，代理支持 /ws 的Upgrade与长连接。只在确需其他网页来源时设置逗号分隔的 ALLOWED_ORIGINS。

只运行一个应用副本，不支持多实例分布式房间。SQLite和MySQL视为独立环境，不自动搬迁历史数据。SQLite位于data/ygoguess.sqlite，停服后备份或使用SQLite备份工具；不要只复制正在写入的数据库文件。

## 测试与验收

```powershell
npm test
npm run build
npm run test:e2e
npm run test:production
```

- npm test：规则、隐私、并发幂等、权限、HTTP/WS、SQLite恢复、缓存回退。
- test:e2e：真实百鸽和卡图，独立浏览器完成两局及第三人中途加入，含聊天、键盘选卡、刷新恢复、手机布局、管理员操作。Windows默认使用Edge；可设置BROWSER_PATH。其他系统可先执行 npx playwright install chromium。
- `npx tsx tests/invite.e2e.ts`：隔离浏览器验证邀请链接优先显示、无效目标保留原房间及切换成功；使用本地测试卡牌，不访问百鸽。
- `npx tsx tests/item-cards.e2e.ts`：隔离浏览器验证禁止卡选人、增殖卡与假面卡的牌面效果、过期恢复和跳过回合；使用本地测试题库，截图保存在 `test-results/item-flow/`。
- `npx tsx tests/new-item-cards.e2e.ts`：隔离浏览器验证机会、雷击、火球、外神、神愤、指名、扫描卡的使用、目标选择、视觉特效及到期恢复；截图同样保存在 `test-results/item-flow/`。
- `npx tsx tests/second-wave-item-cards.e2e.ts`：隔离浏览器验证月书盖放和到期恢复、苏生选择及回合恢复、逆转失败判定与口头约定卡的系统消息；截图同样保存在 `test-results/item-flow/`。
- test:production：配置 MYSQL_TEST_URL / REDIS_TEST_URL 后才跑真实服务，否则显示SKIP；请使用独立测试数据库，仅清理测试生成的记录。
- 测试题目和比赛使用隔离临时数据库，不写入正式精选题库。截图和报告在test-results。本次实际结果见docs/VERIFICATION.md。

## 结构与接口

client：界面、WebSocket重连、卡牌搜索。server：规则、鉴权、卡牌代理、缓存和数据库适配。shared/types.ts：服务器状态、按玩家裁剪的公开状态及消息类型。components/ui保留Sites自带组件；config/card-pool.json是正式题库。

HTTP：GET /api/health、GET/POST /api/session、GET /api/cards/search?q=&start=、GET /admin/entry?key=。WebSocket端点/ws；命令携带id、type，猜测、跳过和放弃本局另带turnId，出题另带setupId。房主移除成员另带playerId。服务器发送snapshot、ack、error、admin-rooms。身份来自Cookie，不信任客户端传入的权限。

外部API请求在提交队列外执行，提交时重新验证游戏阶段。数据库失败不改变已广播状态，重复请求不重复扣次数/加分/跳回合。聊天纯文本，最多500字符，保留最近100条，无专门问答流程。
