# 道具卡框架

卡牌名称、来源、功能与进度记录在[道具卡清单](item-card-catalog.md)。

## 本版规则

- 房主在开局前设置“开启道具卡”，默认开启，两种模式共用。修改后其他玩家重新准备；比赛开始后锁定。
- 每小局按玩家自己的回合数计数，第 3、6、9……次轮到自己时各抽一张；第 1、2 次不发。提前猜中、失败或离场后不再抽取。没用的卡留在本局手牌；进入结算时清空，不带到下一局。
- 卡池按 `shared/item-cards.ts` 中的正权重抽取；忘我卡权重 50。测试卡权重 0，仅保留给调试和旧手牌，不再随机抽到。服务端创建唯一 `instanceId`，同种卡可有多张。每张只能使用一次。
- 仅在猜卡阶段的本人回合使用。使用道具卡不消耗猜测次数，不结束回合，也不改变得分。测试卡没有游戏效果，只在聊天记录写入“玩家名使用了测试卡”。
- 禁止卡选择仍在本局行动的其他玩家；其下次回合被服务端跳过，不增加其个人回合数。多张禁止卡依次跳过后续回合，结算时清除。
- 增殖卡在所有玩家的卡图上叠加原创卡通蟑螂贴图，约每 6 秒变换位置，持续 3 分钟。假面卡为场上每位参赛者分配不同的真实假面英雄卡牌外观，持续 1 分钟；真实题目和猜测判定保持原样，自己的真实答案仍不下发给本人。两种效果重复发动会刷新各自的持续时间，结算时结束。
- 更衣卡选择场上一名有卡牌的玩家（可选择自己），将其卡牌临时替换为随机半龙女仆怪兽外观，持续 1 分钟。随机选定的卡牌通过现有百鸽卡牌接口取得中文卡名和项目统一卡图；接口不可用时不会消耗道具卡。同一目标再次使用会重新随机并刷新时间；更衣外观优先于同时生效的假面外观，结束后仍有效的假面外观继续显示。盖放卡牌期间仍显示卡背，真实题目和猜测判定不变，本小局结算时清除效果。
- 机会卡给自己增加 1 次剩余猜测机会。扫描卡将自己当前卡名中的空格去掉，以 Unicode 字符计数，在公共聊天公布数字而不公布卡名。
- 雷击卡在网页随机展示雷电 3 分钟；火球卡选择场上另一位有卡牌的玩家，给其卡图加燃烧特效 3 分钟；外神卡让所有玩家卡图间歇轻微扭曲 5 分钟。它们都是纯视觉效果，不影响猜卡或得分，重复使用刷新持续时间，本小局结算时结束。
- 神愤卡选择场上另一位有卡牌的玩家，遮挡其卡图顶部的名称及卡图下方名称，仅持续当前小局，不跟随下一小局的新卡。指名卡只公告使用者；被禁止的名词或概念由玩家自行在聊天或线下声明，所有人凭约定遵守，系统不限制提问。
- 月书卡选择另一位有卡牌的玩家，显示[网页取得的游戏王卡背](https://www.vhv.rs/viewpic/TRmmwiw_battles-of-legend-lights-revenge-yu-gi-oh/)并隐藏卡名及放大入口 3 分钟。它只覆盖外观；其他限时视觉效果与神愤遮名在月书到期后按剩余时间继续显示。卡背已压缩成本地 WebP，页面无需访问原站。
- 苏生卡仅能选择仍在本场比赛、在线且因猜错耗尽猜测次数的其他玩家。复活后恢复 1 次机会，保留既有回合数，按原座位顺序等待下次回合。主动放弃、逆转卡跳过造成的失败不能作为目标。
- 逆转卡在本人回合发动；系统公告本回合可问 5 个问题。该回合猜中照常得分，猜错或跳过（包括强制跳过）立即将剩余机会清零并判失败。虚无卡、谜题卡、提示卡和丝袜卡的问答约定只通过道具卡系统消息发布，不增加输入框、计数或聊天拦截。
- 连击卡在本人回合发动；下次提问时，若所有人都回答“是”，就可以继续提问，直到有人回答“否”。仅通过道具卡系统消息公告，由玩家口头遵守；系统不记录或判定问答。
- 小丑卡选择另一位本局玩家，将其玩家列表和聊天中临时显示的昵称改为 🤡，持续 5 分钟；身份和存档中的原始昵称不变，重复指定同一目标刷新时间，本小局结算时恢复。
- 友情卡给使用者与指定的另一名仍在猜卡的玩家各加 1 次剩余猜测机会。团结卡给当前所有仍在猜卡的玩家各加 1 次；已猜中、失败或离场的人不因此重返游戏。
- 终焉卡从使用者的下一玩家回合开始计数，每完成一个实际玩家回合减 1，经过 20 个后强制结束当前小局。被禁止卡跳过而未开始的回合不计。倒计时已开始时不能再次使用终焉卡；若本局提前正常结束则清除倒计时。
- 抢夺卡只能指定另一名仍在猜卡且至少剩余 2 次机会的玩家；将对方剩余机会扣到 1，扣掉的全部加给使用者。设计者：绫奈崎。
- 音乐卡随机播放曲库中的一首游戏王音乐；再次使用会重新选曲，并尽量避开正在播放的曲目。音乐随本小局结束而停止。每位玩家可独立关闭或开启音乐功能，默认低音量；浏览器阻止自动播放时，关闭后再开启可由点击触发播放。
- 忘我卡选择一名其他在线玩家，由对方在中央画板上为使用者的卡牌画提示。固定 5 像素笔刷，不提供颜色、粗细或清空选项；画面实时同步给房间所有人。绘画者点击“关闭画板”结束，使用者或绘画者离场、本小局结束也会关闭。新一次忘我卡会替换当前画板。笔画以 800×500 整数坐标传输，每约 80 毫秒按 Ramer–Douglas–Peucker 算法简化，只广播增量；重连时恢复本次画板已有笔画。笔画仅在服务进程内保留，服务重启后当前画板会从空白开始。

## 音乐曲库

在 `shared/music.ts` 修改歌曲。当前已配置用户提供的 7 个网易云歌曲 ID：`4998139`、`4981014`、`4941629`、`4992324`、`4998138`、`1331144098`、`29482285`。由于无法访问网易云音乐站点核对，曲名和站外播放能力尚未实测；界面暂以 ID 标识未核对的曲目。另有《熱き決闘者たち》《Shuffle》《OVERLAP》《99%》作为候选，确认单曲可以对外播放后再填写对应的 `neteaseId`。未填 ID 的候选曲目不会参与抽取；曲库没有配置 ID 时，音乐卡暂不进入抽卡池（配置后的权重为 50）。网页以低音量使用浏览器原生音频播放网易云音乐单曲外链，不需要额外 SDK；能否播放仍受网易云版权、地区、外链策略和浏览器自动播放限制影响。

## 扩展位置

- `shared/item-cards.ts` 维护卡牌目录：稳定 ID、名称、种类、参考卡、插画、说明和发动时机。种类决定前端卡框颜色：魔法绿、陷阱紫红、普通怪兽棕、超量怪兽黑、同调怪兽白。来源卡只用于设计参考，不在玩家道具卡 UI 下方展示。插画压缩为约 300×300 的 WebP。
- `server/engine.ts` 的 `activate` 负责抽取，`useItemCard` 负责校验、消耗与结算效果。新增真实卡效时在后者按 ID 分派服务端效果，并为其增加规则测试。客户端只负责展示和发送使用请求，不决定抽卡结果或执行效果。
- `Entry.itemCards` 随房间状态持久化；`RoomView.myItemCards` 只下发给本人。观战者、其他参赛者和管理员视图均不包含手牌。存档中缺失开关的旧房间按默认开启处理，缺失手牌的旧局从空手牌开始。
- 命令带唯一请求 ID、卡实例 ID 和当前回合 ID；沿用房间已有的串行提交与去重机制。使用后保存房间，再广播新状态。旧回合、非本人手牌、重复使用及关闭道具卡时的请求由服务端拒绝。
- 看透卡的手牌清单仅在使用者的房间视图中出现，其他人只看到使用公告。天变卡分别将灾难卡加入每人的私有手牌。鲜花、旋风、风暴、陨石、地碎和日书的限时效果随房间状态保存，结算或到期后清除。

## 本地调试

`npm run dev` 中房主可展开“道具卡调试控制台”。它可以单人开测试局、定向发卡、切换回合、调整猜测次数、模拟猜错出局、清空手牌、结束视觉效果和缩短终焉倒计时。单人开局使用本地保存的「青眼白龙」与「黑魔术师」完整卡图及一个测试玩家，不依赖卡牌接口。卡图取自项目使用的 YGOPro 卡图 CDN，对应[青眼白龙](https://ygocdb.com/card/89631139)和[黑魔术师](https://ygocdb.com/card/46986414)。服务端仅在开发模式接受调试命令，并再次校验房主身份；正式服务不提供此入口。测试手牌仍只下发给持有者。

## 后续扩充

新卡继续由会话确定名称、来源、权重、目标、时机及持续范围，再写入卡牌目录和服务端规则。
