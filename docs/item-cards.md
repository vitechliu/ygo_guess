# 道具卡框架

卡牌名称、来源、功能与进度记录在[道具卡清单](item-card-catalog.md)。

## 本版规则

- 房主在开局前设置“开启道具卡”，默认开启，两种模式共用。修改后其他玩家重新准备；比赛开始后锁定。
- 每小局按玩家自己的回合数计数，前 5 次轮到自己时各抽一张。提前猜中、失败或离场后不再抽取。没用的卡留在本局手牌；进入结算时清空，不带到下一局。
- 卡池按权重抽取：禁止卡 100、增殖卡 20、假面卡 50。测试卡权重 0，仅保留给调试和旧手牌，不再随机抽到。服务端创建唯一 `instanceId`，同种卡可有多张。每张只能使用一次。
- 仅在猜卡阶段的本人回合使用。使用道具卡不消耗猜测次数，不结束回合，也不改变得分。测试卡没有游戏效果，只在聊天记录写入“玩家名使用了测试卡”。
- 禁止卡选择仍在本局行动的其他玩家；其下次回合被服务端跳过，不增加其个人回合数。多张禁止卡依次跳过后续回合，结算时清除。
- 增殖卡在所有玩家的卡图上叠加原创卡通蟑螂贴图，约每 6 秒变换位置，持续 3 分钟。假面卡为场上每位参赛者分配不同的真实假面英雄卡牌外观，持续 1 分钟；真实题目和猜测判定保持原样，自己的真实答案仍不下发给本人。两种效果重复发动会刷新各自的持续时间，结算时结束。

## 扩展位置

- `shared/item-cards.ts` 维护卡牌目录：稳定 ID、名称、种类、参考卡、插画、说明和发动时机。种类决定前端卡框颜色：魔法绿、陷阱紫红、怪兽棕。测试卡的视觉参考为游戏王魔法卡“Card Trader”；插画是原创的卡通化空白卡形象。
- `server/engine.ts` 的 `activate` 负责抽取，`useItemCard` 负责校验、消耗与结算效果。新增真实卡效时在后者按 ID 分派服务端效果，并为其增加规则测试。客户端只负责展示和发送使用请求，不决定抽卡结果或执行效果。
- `Entry.itemCards` 随房间状态持久化；`RoomView.myItemCards` 只下发给本人。观战者、其他参赛者和管理员视图均不包含手牌。存档中缺失开关的旧房间按默认开启处理，缺失手牌的旧局从空手牌开始。
- 命令带唯一请求 ID、卡实例 ID 和当前回合 ID；沿用房间已有的串行提交与去重机制。使用后保存房间，再广播新状态。旧回合、非本人手牌、重复使用及关闭道具卡时的请求由服务端拒绝。

## 待定卡效约束

日后扩充卡池时，再逐张确定目标、是否可连锁、是否允许在别人回合发动，以及抽卡权重。
