# 可选粉红登录接入设计

日期：2026-11-04。状态：已本地实现；真实粉红服务与生产部署尚未联调。

## 已确认范围

- 保留现有输入昵称即可创建、加入房间的游客流程。
- 在首页“你的昵称”输入框右侧增加“粉红登录 / 关联”入口，弹窗提供关联码、账号密码两种方式，默认关联码。
- 关联成功用 `core_user.name` 填入游戏昵称，不使用网站账号的 `user.nickname`；之后允许玩家修改游戏昵称，不反向修改粉红账号资料。
- JWT 存入本站 localStorage，尽可能长期保留；不人为增加前端到期时间。
- 服务端验证后将玩家识别为已登录，现阶段不增加权限、奖励、积分合并或其他玩法逻辑。
- 对局开始、结束日志中的账号 ID 使用 **`core_user.id`**，不是网站 `user.id`，也不是游戏 `playerId`。
- `core_user=null` 的网站账号暂不允许粉红登录，提示“请先关联机器人账号”；不建立本站粉红身份，不持久化此次 JWT。
- 同账号不同设备仍是独立游戏玩家。本期不做跨设备房间恢复或玩家、分数合并。

## 现有代码与接口依据

- `client/Home.tsx`：昵称字段和游客提交逻辑；`client/main.tsx`：启动读取 `/api/session`。
- `client/game.tsx`：WebSocket 使用 Cookie 身份，连接随玩家 ID、昵称、管理员状态变化重建。
- `server/app.ts`：游客 Cookie 为 `ygoguess_session`，HttpOnly、SameSite=Lax，有效期 30 天；HTTP 与 WebSocket 都通过 Cookie 读取 Session。
- `server/store.ts`：SQLite/MySQL 以 JSON 保存 Session 和房间，允许兼容性增加可选字段。
- `server/hub.ts`、`server/ops-log.ts`：已提交的房间状态触发异步 `cg_game.started` / `cg_game.ended` 上报，包含昵称、结束结果，异常结束也覆盖。
- `server/engine.ts` 的 `view()` 会展开玩家对象，私有账号字段不能直接添加到 Player 后任其输出。
- 接口文档：`/Users/vitech/after615/holyCityBackend/docs/frontend-auth.md`。
- 已核对后端 `AuthController.php`、`Models/User.php`、`OpsLogReportController.php`、`Utils/OpsLogUtil.php` 和 `config/jwt.php`。本地 JWT 配置 `ttl=null`、无开放 refresh 接口；不能保证生产配置一致或 token 永久有效。

## 接入方式

浏览器直接调用粉红 HTTPS 登录接口，取得 JWT；再将 JWT 通过本站同源 HTTP Authorization 头交给游戏服务端。游戏服务端独立请求粉红 `/api/auth/me`，校验成功后从响应提取账号资料，建立本站已登录会话。

这样密码、关联码只交给粉红后端；游戏服务端不接受浏览器自报的 ID、昵称或已登录标志。WebSocket 保持 Cookie 鉴权，不把 JWT 放进连接 URL、房间消息或游戏命令。

外部地址使用 `https://io2.vitechliu.com`，登录请求带 `source: "ygo_guess"`：

| 调用 | 用途 |
| --- | --- |
| `POST /api/auth/registerByCode`，`{code, source}` | 六位关联码登录；提示从机器人“关联码”指令获取，五分钟有效、成功后失效 |
| `POST /api/auth/login`，`{username, password, source}` | 账号密码登录；账号是用户名，不是邮箱或昵称 |
| `GET /api/auth/me`，Bearer JWT | 由游戏服务端确认身份并获得最新 `core_user.name`、`core_user.id` |
| `POST /api/auth/logout`，Bearer JWT | 明确退出或切换账号时使当前 JWT 失效 |

两种主动登录通过本站校验并保存 JWT 后，在浏览器空闲时使用该 JWT 以低优先级后台调用一次 `POST /api/cgv3/afterLogin`，不等待请求返回、不占用登录串行队列；空闲调度最长等待两秒，不支持空闲调度时使用定时器。无必填请求体，兼容成功响应为空；发送前若账号已解除或切换则取消。调用失败时提示登录后同步暂未完成，保留已成功的登录，不自动重试。页面恢复、重连和定期验证不调用此接口。

浏览器登录调用不携带旧 JWT，不使用跨域 Cookie。请求设超时并禁止重复提交。生产仍需检查部署域名 CORS 和游戏服务器到粉红接口的连通性。

## 本站接口和身份模型

- `POST /api/pink/session`：接收 Authorization Bearer，向固定的粉红后端地址校验身份；有有效 `core_user.id` 才创建或更新本站会话。响应只返回本站需要的身份摘要，不转发整份用户模型。
- `DELETE /api/pink/session`：解除本站粉红身份，保留原游戏玩家 ID，回到游客状态；不授予或更改管理员权限。JWT 的远端退出由浏览器调用。
- `GET /api/session`：兼容性增加自己的粉红身份摘要，如 `pink: {name}`（取自 `core_user.name`），以此显示“已关联”。服务端保留 `user.id` 用于识别账号，`core_user.id` 用于统计。
- 现有 `POST /api/session` 继续处理游客与游戏昵称。已登录玩家修改昵称不能意外清除粉红身份；旧页面不能通过这个接口伪造粉红身份。

Session 增加服务端写入的可选粉红身份字段。JWT 只在请求期间使用，不保存到游戏数据库、房间或日志；Session 保存已验证的身份摘要和校验时间。关联沿用当前 `playerId`，不改变现有 Cookie 身份与房间权限规则。

首次关联、切换账号仅允许在未加入房间时进行，服务器也检查，避免其他标签页绕过。解除入口位于首页；服务器允许房间内撤销身份，以便失效凭证和跨标签页退出及时生效，本局统计继续使用开局快照。房间内允许对当前同一账号重验和恢复，不能借重验改成另一账号或覆盖游戏昵称。修改身份需更新或关闭旧 WebSocket，令后续连接读取最新 Session；仅修改 React 状态不足以更新服务端现存连接。退出时也要使旧粉红会话失效，不能留下仍可重用的旧 Cookie 会话。

## 昵称、持久化和恢复

- 关联成功时把服务端验证返回的 `core_user.name` 填入游戏昵称。先去除游戏不允许的控制字符，再按现有 16 字上限安全截断，避免切断代理对。账号昵称保留完整值；若处理后为空则让玩家自行填写，不回退使用 `user.nickname` 或网站用户名。
- 游戏昵称始终可编辑；页面自动恢复登录时，保留用户已修改的游戏昵称，不反复覆盖。只有首次关联、主动切换账号时自动填入账号昵称。
- localStorage 仅保存 JWT；密码和关联码不持久化，关闭弹窗清空。读取或写入 localStorage 失败需提示“本次可登录，但无法记住登录状态”。
- 页面启动先读 Cookie 会话；存在 JWT 时调用本站粉红会话接口重新校验，完成后再连接 WebSocket，避免恢复成游客后立即发送游戏命令的竞态。
- 若 Cookie 已过期，凭仍有效 JWT 可以新建本站玩家会话，恢复粉红身份；不承诺恢复原 `playerId`、旧房间或积分。
- 启动时验证；有新登录、账号切换或新的 WebSocket 连接时确保校验仍在短期有效窗口内。可先采用五分钟窗口，窗口过期由前端重新提交 JWT 验证，避免每条游戏命令请求粉红接口；服务端不能仅因 Cookie 尚未过期就无限认可粉红身份。
- 401 清除 JWT 和本站粉红身份，保留游客入口；403 显示服务端原因并撤销本站粉红身份，停止自动重试。网络超时、429、5xx 不删除 JWT，显示暂时无法验证，可重试或选择游客继续。
- 长连接内的身份按已验证窗口管理；到期未能重新验证时，后续新局不继续作为已登录参与者记账。已经开始的本局保留开局身份快照，避免开始、结束归属不一致。
- 主动退出：先解除本站身份，再尽力远端注销 JWT，无论远端是否成功最终清除本地 JWT；网络失败应说明退出可能仅在本机完成。跨标签页通过 storage 事件同步清理与重验。

localStorage 没有应用自设的过期时间，但清理站点数据、隐私模式、浏览器回收、服务端注销或密钥变更都可能结束登录；本期不引入不存在的 refresh 接口。

## 日志与房间持久化

保留现有日志字段，建议增加 `metadata.participants`：

```json
{
  "participants": [
    {"playerName": "粉红玩家", "coreUserId": 123},
    {"playerName": "游客", "coreUserId": null}
  ],
  "results": [
    {"playerName": "粉红玩家", "coreUserId": 123, "status": "solved", "points": 1000, "turns": 1}
  ]
}
```

- `participants` 与原 `playerNames` 对应实际参赛 Entry，排除观战者。同一账号多设备参赛按多个参赛者记录，不按账号去重；账号统计端可以另行去重。
- 在开始一局时冻结参赛者身份到房间的独立私有字段，保存游戏玩家 ID 到 `coreUserId` 的映射及必要昵称。游客也明确保存为 null；老房间缺字段按游客处理。
- 结束时使用同一份开局快照，包括玩家离开、切房、管理员解散、闲置超时和重启恢复；不能只查当前在线连接。
- 每局重新生成快照；取消登录不改写历史归属，不追溯补报过去游客对局。
- 私有映射不进入 `RoomView`、`PlayerView`、管理员列表或聊天。不要把身份字段放入会被 `...p` 展开的公共玩家对象。
- 不上报 JWT、Cookie、密码、关联码、网站完整用户资料、题目答案或游戏内部玩家 ID。
- 继续在存储成功后异步上报，失败不阻塞游戏；接收端允许 metadata 数组，已有 12000 字节总载荷上限，实施时验证十人局完整载荷。
